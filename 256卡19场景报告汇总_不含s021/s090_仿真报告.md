## 部署经验（用户提供的公式推导总结）

以下内容按用户提供的总结写入。

统一关系：

$$
N=256,\qquad B=128,\qquad
DP=\frac{256}{PP\cdot TP},
$$

$$
p_E=\frac{E}{EP\cdot C}=\frac8{EP},
\qquad p_E\le1.
$$

因此专家容量要求 \(EP\ge8\)。另外 batch 硬约束 `128 可被 DP×MB 整除`，至少给出：

$$
DP\cdot MB\le128
$$

从而：

$$
\boxed{\frac{MB}{PP}\le\frac{TP}{2}}.
$$

后面凡是利用这条关系，我都会明确说明它来自**可行性约束**，不是 score 偏好。

### s090 经验与推导

比例目标：

$$
0.5\le TP/DP\le2.
$$

TP：

$$
TP\le8.
$$

DP：

$$
DP\ge40.
$$

因此：

$$
\boxed{
PP\cdot TP\le6.4
}.
$$

同样，这使 TP/DP 的目标平台难以进入，因此应：

$$
\boxed{
先满足高DP，再在该区域内尽量增大TP/DP
}.
$$

EP 有两档奖励：

$$
p_E\ge0.5
$$

有 +20，

$$
p_E\ge0.75
$$

再有 +15。

因此完整奖励区：

$$
\boxed{
0.75\le p_E\le1
}
$$

即：

$$
\boxed{
E/C\le EP\le4E/(3C)
}.
$$

显存：

$$
\boxed{
memory\_pressure\ge0.303408
}.
$$

MB 没有直接评分项，只通过显存公式出现，所以不能机械总结为 MB=min。

形状方面，满足 DP≥40 的离散区域中 `PP1_TP4` 给最大的 TP/DP：

$$
PP=1,\ TP=4,\ DP=64.
$$

现在再看 MB。PP1/TP4/EP8 下：

* MB=1 的 memory pressure 高于 0.303408；
* MB=2 会把 activation 压低，使 memory pressure 掉到阈值以下。

因此显存条件进一步推：

$$
\boxed{MB=1}.
$$



**部署经验：**

$$
\boxed{
DP\ge40;\quad
TP\le8;\quad
高DP区域内尽量增大TP/DP;\quad
EP\in[E/C,4E/(3C)];\quad
memory\_pressure\ge0.303408
}
$$

当前参数空间进一步：

$$
\boxed{PP1\_TP4\_DP64\_EP8\_MB1}.
$$

## 4. 字段定义代码与评分函数

以下字段定义位于原始 score 上方，已逐一核对全部 90 个候选的特征及评分结果。

```python
# 定义说明代码：只构造本 score 实际使用的字段。
# 调用前，候选须通过正整数、整除、专家容量和显存可行性检查。
from types import SimpleNamespace


def planned_memory_gib(PP, TP, DP, EP, MB):
    D = 3746457600  # dense 参数量
    X = 32463912960  # expert 参数量
    b = 128 / (DP * MB)  # 每副本每 microbatch 样本数
    local = (D + X / EP) / (PP * TP)
    states = (D / DP + X / DP) / (PP * TP) * 16  # bytes
    gathered = local * 2  # bytes
    activations = (b * 4096 * 2560 * 2
                   * 24 * 44 / PP / TP * min(MB, PP))
    return (states + gathered + activations) / 2**30 + 4  # GiB


def build_ctx(PP, TP, EP, MB, topology=None):
    N = 256  # 可用 GPU 数；全部候选用满卡
    E = 192  # 专家总数
    C = 24  # 每个 EP rank 的专家数上限
    B = 128  # 全局 batch
    DP = N // (PP * TP)  # PP×TP 整除 N；DP 不是独立选择
    ctx = SimpleNamespace()
    ctx.dp_degree = float(DP)  # 数据并行度
    ctx.expert_capacity_pressure = (E / EP) / C  # 每个 EP rank 的专家数 / 上限；不是实测利用率
    ctx.memory_pressure = planned_memory_gib(PP, TP, DP, EP, MB) / (64 * 0.9)  # 规划显存 / 可用显存；无量纲
    ctx.tp_degree = float(TP)  # 张量并行组大小，未取对数或归一化
    ctx.tp_dp_ratio = TP / DP  # 张量并行度 / 数据并行度
    return ctx


def hinge_above(x, a):
    return max(0.0, x-a)  # 超过上界 a 的部分


def hinge_below(x, a):
    return max(0.0, a-x)  # 低于下界 a 的缺口


def distance_to(x, a):
    return abs(x-a)  # 与目标 a 的绝对距离


# 原始评分函数：按原样保留所有条件、阈值及奖惩系数。
def score(ctx):
    score = 0.0
    if 0.5 <= ctx.tp_dp_ratio <= 2.0:
        score += 10.0
    else:
        score -= 10.0 * distance_to(ctx.tp_dp_ratio, 1.0)
    if ctx.tp_degree <= 8:
        score += 10.0
    else:
        score -= 5 * hinge_above(ctx.tp_degree, 8)
    if ctx.dp_degree >= 40:
        score += 10.0
    else:
        score -= 5 * hinge_below(ctx.dp_degree, 40)
    if ctx.expert_capacity_pressure >= 0.75:
        score += 15.0
    else:
        score -= 15.0 * hinge_below(ctx.expert_capacity_pressure, 0.75)
    if ctx.memory_pressure >= 0.303408:
        score += 10.0
    else:
        score -= 50 * hinge_below(ctx.memory_pressure, 0.303408)
    if ctx.expert_capacity_pressure >= 0.5:
        score += 20.0
    else:
        score -= 20.0 * hinge_below(ctx.expert_capacity_pressure, 0.5)
    return score
```

硬约束：PP×TP×DP=256；PP 整除 44；EP 整除 DP 和 192；128 可被 DP×MB 整除；192/EP≤24；规划显存≤57.6 GiB。EP 不额外乘入 GPU 数。
